## 2. The one shared form carries the invoice details

Every SaaS-issued customer link (`https://jriq.in/{slug}`, alias paths, and the legacy
`/store/{slug}` printed QR path) lands on the same form. The invoice/bill field is:

- **optional** - no required marker, no validation, never gates the reward (**Verified**:
  live check 9/9 across `pashupati1`/`pashupati2`/`pashupati`, plus the journey matrix
  where every submission completes to the thank-you screen with the field left empty);
- **stored only** - `submissions.invoice_details` (nullable, length CHECK 1..200); NULL
  when not provided, blank input normalises to NULL (**Verified**: read-back of three
  probe submissions);
- **never rewarding** - reward eligibility, bracket matching and pool selection are
  byte-identical to the previous release (see 3).

  functions yet (they ship with the Kohinoor chain). The platform shop-config panels
  error if used; vendor and customer paths are unaffected (**Verified** in the RPC
  surface diff).

  Actions build); see `docs/DEPLOYMENT.md` A4.
- Wheel animation measured at 6217-6556 ms end-to-end (6000 ms animation + render
  overhead) - inside the required 5-6 s animation window. Reduced-motion users get a
  3000 ms gentle spin by design (accessibility).
- Delivery classification: **complete** - invoice-details behind every link, Pashupati
  three-store acceptance green on the live bundle, all gates executed with evidence.

## 8. Same-day amendment - final live state (v1.4.0, 2026-10-19)

The deployment brief issued later the same day supersedes two release parameters and adds
per-store gift-configuration acceptance. Everything below was executed and verified
against what `https://jriq.in` actually serves.

**What changed after the v1.3.1 tag**

- **Wheel animation is 5 seconds** (`SPIN_DURATION_MS = 5000`; reduced-motion variant
  3000 ms unchanged) - the brief's explicit value supersedes the earlier 5-6 s wording.
  The constant is pinned by `src/components/ui/SpinWheel.timing.test.ts`.
- **Vendor gift editing works end to end**: the owner panel exposes one editable
  gift-name field per configured wheel segment, and the wheel label now follows the
  saved name on edit (`src/features/vendor/Rewards.tsx`; regression-pinned in
  `Rewards.test.tsx`). A deliberately distinct short label is preserved.
- **Gift-columns groundwork** (`supabase/migrations/20261019120000_store_gift_columns.sql`:
  additive `stores.gift_columns jsonb` + `save_store_gift_columns`), applied
  **staging-first then production**. Inert for the three Pashupati stores: their
  `gift_columns` stays NULL and their existing bracket-ladder (amount -> gift) reward
  configuration and engine semantics are preserved verbatim - publishing gift columns
  would collapse the ladder to a single equal-probability bracket, a business-rule change
  this release deliberately does not make.
