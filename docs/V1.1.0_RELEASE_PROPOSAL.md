Status: **AWAITING EXPLICIT APPROVAL** — production untouched since v1.0.0.
Candidate: `7cbe8d69dd3ab0f64c09578671590349cbc70647` (branch `staging`, pushed,

## 2. Route table (candidate)

| URL | Behaviour |
| --- | --- |
| `/` | JRIQ platform homepage — never auto-redirects |
| `/{slug}` | customer spin & win; unknown slug -> designed 404; suspended/onboarding -> inactive page |
| `/{slug}/admin` (+ `/dashboard|customers|rewards|qr-code|settings`) | vendor workspace: anon -> login wall; signed-in non-owner -> 403 with zero shop data |
| `/store/:slug` | permanent lossless client redirect -> `/{slug}` (physical QR cards) |
| `/platform/*` | unchanged (platform console) |
| `/vendor/*` | legacy redirects -> `/{slug}/admin/*`; the slug is resolved from the authenticated `store_admins` context, never the URL |
| `/standee/:slug`, `/privacy` | unchanged (standee is now strict-slug) |
| reserved segments + `public/` filenames | system routes and real files win; `/:slug` catch-all is dead last |
| anything else | designed "Page not found" |

## 4. Security results (Phase 3 slug-swap suite — 72/72, staging)

- **L1 reserved wall**: all 23 reserved names rejected by `create_shop` at the
  RPC; direct insert rejected by `stores_slug_reserved_check` (live probe
  returned `GOOD-CHECK`); pattern rejects uppercase/double-dash; control shop
  creates fine and returns root-level `customer_path`.
- **L2 cross-tenant raw-RPC (owner A vs shop B)**: `is_store_admin` false;
  `admin_save_store_tiers` / `set_store_status` / `link_store_owner` /
  `create_shop` -> "Platform access is required"; `save_store_gift_options` ->
  "Store workspace access is not active"; `mark_submission_collected` ->
  "Customer record not found"; RLS reads of shop B submissions / store_admins /
  gift pools return 0 rows; owner B cannot rewrite shop A tiers ("belongs to
  another store"); positive control: owner A's self-scoped RPC writes shop A
  only (shop B untouched) — the interface has **no slug/store parameter to swap**.
- **L3 anon walls**: every admin RPC denied (incl. `is_store_admin` -> 42501);
  private-table reads 0 rows; claim records immutable to anon.
- **L4 platform surface**: ordinary owners get 42501-class denials
  (anon `create_shop` -> `42501 permission denied for function`).
- **L5 suspended blocks submissions** backend-side ("Campaign is unavailable"),
  restored after.
- **L6** `customer_path` is root-level `/{slug}`.
- **L7** an unknown address never resolves to a different shop.

URL acceptance (Phase 4 — 72/72 = A1-A9 x 2 real builds, hard refresh each,

## 6. Production migration list (apply at deploy, in order)

1. `20261016090000_reserved_slug_guard.sql` — pre-check (refuses if any existing
   slug is reserved; `jolly-enterprises` verified safe), additive CHECK
   `stores_slug_reserved_check`, `create_shop` replacement (explicit reserved
   rejection + `customer_path := '/' || p_slug`).
2. `20261016100000_inactive_store_notice_read.sql` — second SELECT policy
   "Public can read addressable stores" (`using (active)`); the existing
   "Public can read active stores" policy is untouched (RLS policies OR).

Both are append-only and data-free; both are applied and history-recorded on
staging (history = 10). Each migration header documents its own SQL rollback.

## 8. Rollback

- **Frontend**: redeploy the v1.0.0 `dist/` (tag `v1.0.0 -> a63ca38`, retained).
  Physical QR cards use `/store/{slug}`, which the old bundle serves natively —
  customer links never break in either direction.
- **Database**: both migrations are additive; rollback SQL (documented in each
  header) = drop `stores_slug_reserved_check`, restore `create_shop` from
  `20261015161200`, drop policy "Public can read addressable stores". No data is
  touched in either direction; claims remain immutable (FK + snapshot).
- **Sequence**: front end first (fast), SQL second (only if a defect needs it).
